### Найденные и исправленные баги (важно на будущее)
- **Supabase-js v2: вызов `.from(...).update(...)` без `.then()`/`await` НИКОГДА не уходит на сервер** — конструктор запроса в этой библиотеке «ленивый» (thenable), запрос реально уходит только когда вызывается `.then()` или `await`. Из-за этого не работали: (1) простановка `verified=true` при одобрении зачётки в `admin.js`, (2) весь онлайн-счётчик в `presence.js` (обновление `last_seen_at` вообще никогда не срабатывало). Правило на будущее: **каждый вызов `.from()/.storage.from()` обязан заканчиваться `.then()` или стоять за `await`, без исключений**, даже если результат не нужен — иначе тихо ничего не произойдёт, без единой ошибки в консоли.
- PostgREST embedding падает с «more than one relationship was found», если в таблице два внешних ключа на одну и ту же таблицу (у `verification_requests` — `profile_id` и `reviewed_by`, оба на `profiles`). Лечится явным указанием колонки: `profiles!profile_id(...)` вместо просто `profiles(...)`.
- Функция с `returns table(id uuid, is_admin boolean, ...)` — внутри тела эти имена конфликтуют с обычными колонками в подзапросах без алиаса («column reference is ambiguous»). Всегда алиасить таблицы в теле такой функции (`from public.profiles pr where pr.id = ...`), не полагаться на короткие имена.
- Тип `auth.users.email` — `varchar(255)`, а не `text`; в функции с `returns table(..., email text, ...)` нужно явно приводить (`u.email::text`), иначе «structure of query does not match function result type».
- `alter table storage.objects enable row level security` — нельзя, это системная таблица не в вашем владении («must be owner of table objects»), и не нужно — там уже включено по умолчанию.
- В Supabase SQL Editor кнопка создания новой SQL-вставки открывает выпадающее меню с похожими пунктами «Create a new snippet» (то, что нужно — обычный Postgres SQL) и «Create a new logs query» (ClickHouse SQL для логов, выглядит похоже, но это другой язык и другая база) — если видишь баннер «Logs now run on a ClickHouse-backed engine», значит попал не туда.
- «Success. No rows returned» в SQL Editor означает это и для `UPDATE` тоже — не показывает число изменённых строк, полагаться на текст нельзя, проверять результат отдельным SELECT/запросом из кода.

## Технические заметки (чтобы не наступать на грабли повторно)
- **Кэш браузера в Browser pane**: css/js/картинки кэшируются отдельно от HTML. При правке общего файла — версионировать запрос (`?v=N`) во ВСЕХ ссылающихся страницах и бампать номер.
- Custom viewport ширины >~900px в этой панели превью иногда рендерят скриншот криво (контент сжат в угол) — это баг инструмента; широкую раскладку проверять через `getBoundingClientRect`/computed style в JS, не на глаз, и возвращать `resize_window` к preset `"desktop"` после проверки.
- **CSS-`transition` «зависает» на середине, пока браузерная панель скрыта/не в фокусе** (нашёл на `.ad-popup`, веха 30) — `getComputedStyle` может показывать промежуточное значение (или даже стартовое) сколько угодно долго при пассивном опросе, хотя класс `.show` уже стоит. Это не баг вёрстки: прямой тест с явным ожиданием двух `requestAnimationFrame` подряд подтвердил, что переход реально доезжает до конца (`bottom:16px`, `opacity:1`) — просто скрытая вкладка не дорисовывает кадры сама по себе. Для проверки `transition`/анимаций в этой панели: либо вызывать `requestAnimationFrame` дважды перед чтением `getComputedStyle`, либо не полагаться на итоговые координаты при пассивном поллинге — полагаться на классы/CSSOM-правила и логику.
- Скриншот в этой панели иногда «опаздывает» и показывает пустое/старое состояние сразу после клика или навигации, хотя DOM уже обновился — если скриншот выглядит пустым/неожиданным, сначала проверить через `elementFromPoint`/innerHTML в JS, потом переснять скриншот ещё раз, не считать сразу багом сайта.
